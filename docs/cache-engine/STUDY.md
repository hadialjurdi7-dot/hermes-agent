## 2) تصحيح الفكرة قبل الكود

عند DeepSeek/opencode (ومعظم المزوّدين المتوافقين مع OpenAI):

- **Cache read** = البادئة التي أرسلتها سابقاً بحروفها نفسها → تُحسب بـ1/50 من السعر العادي، ولا تُولّد كاش مكتوب (cache write = 0 عند DeepSeek؛ يُحتسب تلقائياً).
- **Cache miss** = كل توكن جديد أو أي توكن بعد نقطة تغيّر في البادئة. **أي تعديل في منتصف الرسائل يُبطل الكاش من نقطة التعديل لآخر السياق.**
- لذلك القاعدتان الحاكمتان:
  1. **Append-only**: لا تُعدّل رسالة قديمة أبداً (لا اختصار، لا حذف، لا إعادة ترتيب).
  2. **البادئة الثابتة أولاً**: كل ما يتغيّر (وقت، نتائج أدوات) يكون في **آخر** الرسائل.

> لهذا السبب بالذات أي «ضغط سياق» أو «تقليم» في المنتصف يبدو أنه يوفّر، ثم يرفع الفاتورة: يمسح الكاش كله خلف نقطة التعديل.

## 4) نموذج الكلفة

لكل نداء:

```
cost = in_new · P_in + cache_read · P_cache + out · P_out      [لكل مليون توكن]
P_in=0.30 · P_cache=0.006 · P_out=1.20   (DV4.1-Flash peak)
```

وبما أن `in_new ≈ out(t-1) + tool_result(t)`، فإن الفاتورة ≈ **حجم ما تولّده + حجم ما تدخله من أدوات**، مضروباً في $0.30، إضافة لإخراج بسعر 4× الإدخال.

**سقف التوفير النظري (بلا خسارة جودة):**

| المحرّك | الآلية | التوفير الأسبوعي المقدّر |
|---|---|---|
| تقليم بادئة (تفكير + فهرس مهارات + ذاكرة) | cache read أصغر، miss أرخص | $1.2–1.8 |
| سقف إدخال نتائج الأدوات (3k توكن افتراضي) | إدخال جديد أقل | $2.0–2.8 |
| قراءة دلتا للأدوات (diff بدل الملف كامل) | إدخال جديد أقل | $0.8–1.2 |
| مؤشرات بدل النصوص الكاملة (`skill_view`/`session_search`/`memory_recall`) | إدخال جديد أقل | $1.0–1.5 |
| ضبط الإخراج (نثر أقل + تجميع استدعاءات) | إخراج أقل + نداءات أقل | $1.0–1.5 |
| **الإجمالي** | | **$6–8.8 من $19.6 = 30–45%** |

## 5) الخوارزمية — CEE (Context Economy Engine)

### 5.1 المكوّنات الستة

```
CEE = PrefixGuard + BudgetAllocator + EntryClipper + DeltaReader + PointerStore + OutputDiscipline
```

**(1) PrefixGuard** — يحرس ثبات البادئة:
- يمنع أي تعديل على رسائل مؤرشفة (فهرس `frozen_upto`).
- يرفض أي عملية تقليم/ضغط تمسّ رسالة قبل `frozen_upto` (يسمح فقط بالإضافة).
- يقيس `prefix_hash` لكل نداء؛ إن تغيّر بلا سبب مشروع → يسجّل تحذيراً (سبب 90% من ارتفاع الفاتورة الصامت).

**(2) BudgetAllocator** — يوزّع ميزانية توكن على مكوّنات النداء:

```
B_total            = 100% من نافذة السياق
B_system (ثابت)    ≤ 15%      # برومبت + ذاكرة + فهرس مهارات
B_tools_schema     ≤ 10%
B_history (بادئة)  ≥ 55%      # لا تُمسّ (كاش)
B_new (متغيّر)     ≤ 20%      # الرسائل الجديدة + نتائج الأدوات
```

كل ما يتجاوز `B_new` يُحوّل إلى مؤشر (PointerStore) لا إلى نص.

**(3) EntryClipper** — سقف لكل نتيجة أداة عند الإدخال:

```
cap(tool) = base 1,200 tok · hard 6,000 tok
```
- يُبقي الرأس والذيل (head 60% / tail 40%) لأن الأخطاء والنتائج الحاسمة في الأطراف.
- يحفظ الأصل كاملاً في PointerStore ويضيف سطراً: `[full: ccr:8f2a… · 18,240 tok]`.
- الأدوات الكبرى (`web_extract`, `skill_view`, `session_search`, `memory_recall`) لها `cap` أدنى (800) + إلزام استرجاع الأقسام عند الحاجة.

**(4) DeltaReader** — للأدوات ذات الحالة:
- `read_file` على ملف مقروء سابقاً **بنفس الجلسة** → يُعيد فقط الأسطر المتغيّرة ±3 سياق (unified diff) مع بصمة `sha` للسطر الأول/الأخير.
- نفس الشيء لـ`terminal` على أوامر متكررة: resend يُستبدل بـ«لا تغيير منذ #N».

**(5) PointerStore** — مخزن محتوى معنون بالهاش (سبق أن وُجد عندنا كـCCR):
- `put(content) -> ccr:hash`
- `get(hash, ranges)` بأداة جديدة `fetch_context(hash, start, end)` — استرجاع انتقائي بلا إعادة الكل.
- السياسة: لا يُرسَل أكثر من `cap` أبداً؛ الاسترجاع قرار الموديل (escalation prompt: «لو تحتاج تفاصيل قل `fetch_context`»).

**(6) OutputDiscipline** — ضبط المخرَج:
- `reasoning_budget` حسب صعوبة المهمة (router موجود: smart_reasoning_router) — high للمعقد، none/low للبسيط.
- تجميع الاستدعاءات: منع أكثر من X نداء أداة متتابع بلا نتيجة جديدة (كشف الحلقات).
- منع سرد العمليات: الرد بلا تعداد خطوات إلا عند الطلب.

### 5.2 حلقة النداء (pseudocode)

```python
def before_llm_request(messages, tools, cfg):
    # 0) حرس البادئة
    prefix_hash = sha(messages[:frozen_upto])
    if prefix_hash != expected: log_prefix_drift()

    # 1) ميزانية
    used_system = count(messages.system) + count(tools)
    budget_new  = cfg.B_total - used_system - count(messages[:frozen_upto])
    if budget_new < cfg.min_new: return compact_at_boundary(messages)  # عند حدود الدور فقط

    # 2) تمرير على الرسائل الجديدة فقط
    for m in messages[frozen_upto:]:
        if m.role == "tool":
            m.content = EntryClipper.apply(m, cap=cap_for(m.tool_name))
            if dropped: m.content += f"\n[full: {PointerStore.put(original)}]"
        if m.role == "assistant" and cfg.trim_reasoning:
            m.reasoning_content = trim(m.reasoning_content, keep=cfg.reasoning_keep)
    # 3) لا تعديل قبل frozen_upto — أبداً
    return messages
```

### 5.3 قواعد القبول (Definition of Done)

- إصابة الكاش لا تنزل عن **93%** (قياس أسبوعي).
- توفير ≥ **25%** من الفاتورة على 20 مهمة مرجعية (golden tasks) بنفس جودة الجواب (±3 نقاط على مقياس 20).
- لا زيادة في عدد النداءات > 10% (منع إعادة الاسترجاع المفرط).
- كل أداة تحتفظ بمخرجها الكامل قابلاً للاسترجاع (بلا فقدان بيانات).

## 7) خطة التنفيذ

**المرحلة 0 — مسطرة القياس (نصف يوم).**
سكربت `scripts/cee_probe.py`: يقرأ `state.db` ويطلع جدول «كلفة لكل أداة / لكل جلسة» + نسبة الكاش + أكبر 10 مصادر. لا تغيير سلوك.

**المرحلة 1 — EntryClipper + PointerStore (يوم–يومان).**
بلغن `plugins/cache-engine/` يسجّل `llm_request` middleware. يقتصر على تقليم نتائج الأدوات + حفظ الأصل + سطر المؤشر. أداة `fetch_context`.

**المرحلة 2 — DeltaReader (يوم).**
diff للقراءات المتكررة على `read_file`/`terminal`، مع تسجيل نسبة الدلتا.

**المرحلة 3 — PrefixGuard + BudgetAllocator (يوم).**
حرس البادئة + ميزانية الكتلة + كشف انحراف الكاش.

**المرحلة 4 — OutputDiscipline (يوم).**
ربط `reasoning_effort` بالـrouter، تجميع الاستدعاءات، منع الحلقات.

**المرحلة 5 — A/B + تقرير (نصف يوم).**
20 مهمة مرجعية × (on/off) → جدول توفير + فحص جودة بعيّنة عمياء.

الإجمالي المقدّر: **4–5 أيام عمل** لمحرّك مكتمل، و**نصف يوم** لأول نتيجة مقيسة (المرحلة 1 وحدها تعطي أغلب التوفير).

## 8) المخاطر والحدود

| الخطر | التخفيف |
|---|---|
| تقليم مفرط يفقد تفصيلاً حاسماً | مؤشر + `fetch_context` + سقوف متدرّجة حسب الأداة |
| تعديل في المنتصف يمسح الكاش | PrefixGuard يمنع الكتابة قبل `frozen_upto` |
| إعادة استرجاع مفرطة (نداءات أكثر) | عدّاد escalation؛ إن تجاوز 10% → رفع السقف تلقائياً |
| التفكير المخفَّض يضر المهام المعقّدة | تمرير الصعوبة من router؛ سقف أدنى للأنماط العميقة |
| اختلاف المزوّد (بعضهم يفرض إعادة التفكير) | كشف القدرة + fallback (لا تقليم تفكير إن كان إلزامياً) |
| قياس على أثر جانبي (cron ما) | فصل إحصاءات الجلسات التفاعلية عن الكرونات |

**الحدود المعروفة:** لا يمكن تجاوز كلفة الإخراج الأساسية (الموديل لازم يكتب)؛ ولا تجاوز كلفة أول إرسال لأي محتوى جديد. المحرّك يقلّص **التكرار** و**الحجم**، لا العمل نفسه.

## 9) البدائل التي رفضناها ولماذا

1. **زيادة نسبة الكاش إلى 100%** — مستحيل: كل توكن جديد يُدفع مرة واحدة على الأقل.
2. **ضغط السياق دورياً** — يمسح الكاش خلف نقطة التعديل؛ مكسبه وهمي (هذا ما قاسته تجربة Headroom عندنا: 0.24% توفير حقيقي).
3. **إرسال سياق مصغّر للموديل نفسه** — يفقد الدقة؛ البديل: مؤشرات + استرجاع انتقائي.
4. **موديل أرخص فقط** — يعالج 1/3 المشكلة (السعر) ولا يعالج الحجم؛ ويُستخدم كطبقة إضافية لا بديل.
